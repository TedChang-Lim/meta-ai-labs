## 새로 생긴 것

- **HWPX 생성** — 마크다운 → 공문서 서식 HWPX. 프리셋(보고서·기안문 등)
- **부서 서식 견본** (`--template`, 4.23.0) — 기존 HWPX의 제목표·담당 줄·요약 상자·□○ 항목·※ 부호 서식을 그대로 두고 새 원고만 채운다. header.xml 유지, 표·그림 id 재발급, 줄 배치 캐시·누름틀·각주는 제거
- **예산 검산** (4.23.0) — `단가 × 수량 × 기간 = 금액` 곱셈 검산, 표 합계 재계산, 소계(A)/소계(B) 인식, 바른 금액 제안
- **블록 단위 검수** (`lintBlocks`, 4.24.0) — 열린 문서의 문단·표 칸을 id 붙은 블록으로 받아 위치까지 짚어 준다
- **공문서 문체 게이트** — `~다` 서술형 종결을 잡는다(실측 0% 기준)
- MCP 도구 18개

## 융합 판단

**kordoc이 이미 이긴 영역** — 새 문서 생성, 서식 견본 승계, 양식 채우기, 도장 날인, 예산 검산, 표 구조 파싱. 우리가 python-hwpx로 조각을 손으로 맞추던 일은 여기서 끝내는 게 맞다.

**우리가 계속 가져야 할 영역**
- **문서 내용 자체** — 논문·계획서의 논리, 문장, 근거. kordoc은 그릇만 만든다
- **한컴 실물 확인** — 렌더와 실물 뷰어는 다르다. 페이지 넘김·머리말 자리 같은 함정은 여전히 사람이 본다
- **판단이 필요한 조판** — kordoc은 규칙으로 처리하지만, "이 표를 어디에 둘지"는 사람 몫

**결론**: 재구현하지 않는다. kordoc을 축으로 삼고, 우리는 내용과 최종 검수에 집중한다.

## 맥북에서 이어서 할 일

1. 졸업계획서·논문 HWPX를 `--template` 방식으로 다시 뽑아 기존본과 비교
2. 한컴오피스에서 열어 쪽 넘김·머리말 확인 (마스터님 육안)
3. `kordoc lint --budget`을 새미새론 견적서·청구서에 물려 검산 자동화
4. `lintBlocks`를 편집 루프에 붙일 수 있는지 확인 — 열린 문서 실시간 검수
5. 공문서 프리셋의 `~다` 문체 게이트를 우리 문서 문체에 맞게 쓸지 판단
